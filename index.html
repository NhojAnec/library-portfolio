Online Library Management System

ระบบจัดการห้องสมุดออนไลน์

A website for running a small library. Students sign up, browse the books and reserve one to pick up. Librarians log in to a separate admin panel to manage books, authors, categories and students, and to record when books come back.

PHP 8 MySQL / MariaDB PDO jQuery AJAX Bootstrap 3 Runs on XAMPP
Open the original website Open the admin panel View the PHP code on GitHub

The first two open the real site in a new tab. They work on the computer where XAMPP is running, with Apache and MySQL started.

How it works

The life of one loan

Each step shows the real page as it looks in the browser. The screenshots were taken from the site running on XAMPP with the test data from library.sql.

  1. Student · signup.php

    Register

    The site reads the last number from studentid.txt, adds 1, saves it back, and stores the new student in tblstudents with an MD5 password.

  2. Student · index.php

    Log in

    The email and hashed password are checked against the database. On success the student ID is saved in the session as $_SESSION['stdid'].

  3. Student · view-books.php → booking.php

    Reserve a book

    The student presses Book next to a title, then picks a pickup time. In one transaction the site adds a row to tblissuedbookdetails and runs Quantity = Quantity - 1 on the book.

  4. Admin · manage-history.php

    See the loan

    The history table joins loans, students and books, and shows "Not Taken Yet" in red until a return date is entered.

  5. Admin · update-issue-bookdeails.php

    Record the return

    The librarian presses Edit, then types the return date and any fine. The loan is updated and the copy is meant to go back on the shelf.

  6. Student · issued-books.php

    Check the record

    The student sees the return date and fine on their own history page.

What I practised

    
Skills used

    
    
      
  • Sessions and logins
    Two separate logins. stdid keeps a student signed in and alogin keeps an admin signed in. Every protected page checks for one before it shows anything.
    • 
      
  • Prepared statements
    All queries go through PDO with bindParam, so typed input can't change the SQL.
    • 
      
  • SQL joins
    Book lists and loan history join three tables to show names instead of ID numbers.
    • 
      
  • Transactions
    Booking adds the loan and lowers the copy count together, and rolls both back if either fails.
    • 
      
  • AJAX with jQuery
    Signup checks if an email is taken, and admin forms look up student and book names, all without reloading.
    • 
      
  • Full CRUD
    Create, read, update and delete for books, authors and categories.
    • 
      
  • Input checks
    Password confirmation on signup, and a date format check (YYYY-MM-DD HH:MM:SS) on booking.
    • 
      
  • Bootstrap layout
    A responsive menu, panels and data tables shared by every page through header.php and footer.php.

Known issues

    
Problems and bugs I left in

    
I closed the project with these still in the code. They are listed here as they are, without fixes.

    
Bugs

    
    
      
  • Returning a book removes a copy. In admin/update-issue-bookdeails.php, $returnstatus is used before it gets a value. Every save runs Quantity - 1 instead of Quantity + 1, and the loan's status is saved empty.
    • 
      
  • RetrunStatus means opposite things. booking.php saves 1 for "not returned yet", but the student dashboard counts 0 as not returned. Books reserved online never appear in "Books Not Returned Yet".
    • 
      
  • Two students can get the same ID. signup.php reads and rewrites a number in studentid.txt. Two sign-ups at the same moment can get the same ID.
    • 
      
  • Admin "Issue a new book" goes to a missing page. admin/issue-book.php redirects to history.php and manage-issued-books.php, which aren't in the project.
    • 
    

    
Problems

    
    
      
  • Passwords use MD5. MD5 is fast to crack. password_hash() would be safer.
    • 
      
  • Redirects don't stop the page. There's no exit; after header('location: ...'), so the rest of a protected page still runs for someone who isn't logged in.
    • 
      
  • Errors are hidden. Most pages start with error_reporting(0), so database and PHP errors don't show.
    • 
      
  • The booking page prints a warning. booking.php turns error display on, so on newer PHP it shows a deprecation notice about PDO::MYSQL_ATTR_INIT_COMMAND above the header.
    • 
      
  • Read-only fields can be changed. The admin update form trusts the student ID and book ID sent by the browser.
    •
